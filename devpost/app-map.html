HISSTORY: app map

A short guide to how your game is put together and where to look when you want to change something. It's a snapshot of the code at commit bd25b00, so it can drift as the game changes.

The big picture

HISSTORY is one web page with one <canvas>. There's no game engine and no server. Four kinds of code work together:

  • The engine (src/engine/): the game loop, drawing on the canvas, keyboard and touch input, and switching between screens.
  • The rules (src/game/): the snake, fruit, collisions, coil detection, bosses, lives and chapters. This is plain TypeScript with no drawing in it, so it can be unit-tested and saved as JSON.
  • The screens (src/scenes/): Home, Map, Cutscene, Play, Pause and so on. Each screen asks the rules what happened, then draws it and plays the sounds.
  • Sound, art and story (src/audio/, src/art/, src/story/): a home-made chiptune synth, sprites written as text grids, and all the dialogue as data.

Progress is saved in the browser's localStorage (src/save/save.ts).

One action, end to end: you press D and Pip turns right

The route reference route

Follow these in your editor. Each stop links what you see on screen to the code behind it.

  1. src/engine/loop.ts: search for private frame =

    The game loop. Real time is poured into acc and drained in fixed slices of FIXED_DT (1/120 s). Each slice runs one update, then the frame is drawn once. That's why Pip moves at the same speed on a 60 Hz phone and a 144 Hz monitor.

    The core of it 
    this.acc += delta;
while (this.acc >= FIXED_DT) {
  this.hooks.update(FIXED_DT);
  this.acc -= FIXED_DT;
}
this.hooks.render();
  2. src/scenes/PlayScene.ts: search for this.stepAcc += dt * 1000

    The snake's own clock. Inside the fixed updates, stepAcc fills up. Each time it passes stepMs, the rules run one world.step(). That's when your queued turn is applied, and when fruit, crashes and coils are checked.

  3. src/scenes/draw.ts: search for export function drawSnake

    Canvas. alpha is how far (0 to 1) we are between two steps. The head is drawn part-way between its last cell and its new one, and the body is a tube of rectangles, so movement looks smooth instead of jumping cell to cell.

Bonus stop: Web Audio, the same idea for music

src/audio/sequencer.ts: search for private tick(). A cheap 25 ms timer wakes up and schedules every note due in the next ~120 ms on the audio clock (stepsDue). Because notes are booked slightly ahead on that precise clock, the music never stutters, even when the game is busy. The songs themselves are note text in src/audio/tracks/core.ts.

A practice to reuse

Play-test the risky core first, then pin the fix down with a rule you can test.

The build put the kernel, coil to conquer, in slice 2, before any menus, music or story existed. The first hands-on check found it "too much precision". The fix didn't come from guessing. "A coil" was redefined as an observable rule, circling about 300° around the boss (windingDegrees in src/game/coil.ts), with unit tests in tests/unit/coil.test.ts that lock in what counts: gaps are fine, three-quarters of a lap isn't enough, and wall pins work. The PRD and spec were then updated to match.

On your next project, put the riskiest piece first, get your hands on it early, and when something "feels wrong", turn the fix into a sentence you can test.

Run it again

npm install
npm run dev        # http://localhost:5173
npm test           # unit tests
npm run e2e        # browser tests (desktop and phone sizes)
npm run build      # the site, in dist/

Debug shortcuts: ?debug=1&chapter=N jumps to any chapter. In debug mode, I toggles invincibility and N clears the level.
